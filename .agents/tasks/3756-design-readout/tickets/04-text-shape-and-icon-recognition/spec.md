## What to build

The run now decides, per extracted node, what it recognizes. Text-shape rules fire first: address,
transaction and method hashes, block / batch / epoch numbers, timestamps, tickers, NFT ids — after
normalizing lookalike characters (Cyrillic `х` in `0х05…`). A truncated hash with no icon next to it is
always Ambiguous. Then icon recognition matches a normalized instance name against the generated sprite
name list. Each node gets a status (recognized / ambiguous / unrecognized), the decision so far (what the
shape says it is, which signal fired) and that lands in the sidecar. Stdout ends with the count of
Recognized nodes and the full Ambiguous and Unrecognized lists with their resolved values — never a
guessed component.

## Acceptance criteria

- [ ] Text-shape rules are a table of named signals with specs per signal, including a lookalike case
      and the truncated-hash-without-icon → ambiguous rule.
- [ ] Icon matching normalizes the Figma instance name (case, separators, a trailing size or variant
      suffix) and matches against the `IconName` union read from `public/icons/name.d.ts`; a miss is
      Unrecognized with the raw instance name; specs cover hit, normalized hit and miss.
- [ ] Recognition runs in the spec's priority order and records `signal` on the decision; the sidecar
      record has `status` and `decision` filled.
- [ ] Stdout: Recognized count, Ambiguous list, Unrecognized list, each item with node id, values and
      bounding box; a spec renders a small fixture.
- [ ] `CONTEXT.md` where-to-look table points at the rules table and the status vocabulary.

## Details

- Read the sprite names from `public/icons/name.d.ts` (tracked, generated by `svg:build-sprite`) at
  run time rather than from `src/sprite/icons/`, so the tool and the type stay in step.
- Shape rules are regexes plus a normalizer; keep each rule's example in its spec as the documentation.
